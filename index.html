03 / Engineering notes

Problems worth telling

RAG & Evals Peatying

An LLM judge that graded the bot with its own evidence

What went wrong

The first faithfulness harness only showed the judge the chunks the chatbot had already retrieved, which let unsupported or cherry-picked claims look well supported.

How it was fixed

Split every answer into individual attributed claims and retrieved the most relevant corpus passages independently per claim — measuring 98% vs. 73% supported claims against the same model without retrieval (30 hand-written questions, articles only, single run).

RAG & Evals Peatying

The Spanish translation won every search

What went wrong

raypeat.com hosts a few translations. With multilingual embeddings, a Spanish question matched the one Spanish article regardless of topic.

How it was fixed

Removed the translations from the corpus and made the full-text keywords English-only.

RAG & Evals Peatying

The bot retracted true statements

What went wrong

In follow-ups the bot no longer saw earlier sources, so when a new search didn't find a fact it "corrected" itself.

How it was fixed

Fixed in the prompt and verified with repeated runs.

Privacy / PII Peatying

A personal-data filter that ate "Energía celular:"

What went wrong

Users paste medical lab reports with ID numbers into chat, so messages are redacted before storage. The first regex treated celular ("mobile phone" in Latin American Spanish) inside "Energía celular:" (cellular energy) as a phone label and wiped the sentence.

How it was fixed

Restricted everyday ambiguous words to match as PII labels only at the start of a line, and added regression tests with bot-style answers.

Security / SAML Banking APIs

Line separators and signing order in SAML 2.0 XML assertions

What went wrong

When generating signed and encrypted SAML 2.0 responses for external SSO, platform-dependent line endings broke XML signature verification downstream, and encrypting before signing invalidated the assertion digest.

How it was fixed

Enforced strict ordering (sign assertion with RSA-SHA256 + exclusive C14N, encrypt with AES-256 / RSA-OAEP, then sign the outer Response), normalized \n line endings during signing, and disabled DTDs and external stylesheets against XXE.
